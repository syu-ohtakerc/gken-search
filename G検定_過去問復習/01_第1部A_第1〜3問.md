# 第1問:多クラス分類

## 1. 問題の概要
多クラス分類に関する説明のうち**最も不適切なもの**を選ぶ問題(「不適切」を選ぶ形式に注意)。

## 2. 正解
「データセットが均衡・不均衡であるかで、学習手法を変えなくても精度への影響は十分小さい。」(これが**不適切**な文なので正解)

## 3. 正解となる理由
クラス不均衡(クラスごとのデータ数に大きな偏りがある状態)は、学習にも評価にも大きく影響します。
- 多数派クラスだけを予測しても損失が小さくなるため、モデルが**多数派ばかり予測**しやすい。
- Accuracy(正解率)は見かけ上高くなる(例:99%が「正常」のデータで、常に「正常」と答えれば99%)。
- したがって「影響は十分小さい」は誤り。サンプリング、クラス重み、適切な評価指標の選択が必要。

## 4. 関連技術の仕組み

### 4-1. 多クラス分類とは
クラスが3つ以上ある分類(例:手書き数字0〜9、動物の種類)。クラスが2つなら**二値分類**。1つのデータに複数ラベルを同時に付ける場合は**マルチラベル分類**で、多クラス分類(1つだけ選ぶ)とは別物。

### 4-2. ロジスティック回帰の多クラス対応
- 二値の場合:シグモイド関数 σ(z) = 1 / (1 + e^(−z)) で確率を出す。z = w・x + b(w:重み、x:特徴量、b:バイアス)。
- 多クラスの場合(2通り):
  1. **ソフトマックス回帰(多項ロジスティック回帰)**:各クラス k のスコア z_k を計算し、
     P(y=k | x) = exp(z_k) / Σ_j exp(z_j)
     とする。全クラスの確率の合計が1になる。損失は**交差エントロピー**。
  2. **One-vs-Rest(OvR)**:クラスごとに「そのクラス vs それ以外」の二値ロジスティック回帰をK個作る。
- ニューラルネットワークの出力層でソフトマックスを使うのも同じ考え方。

### 4-3. SVMの多クラス対応
SVM(サポートベクターマシン)は、**マージン(境界と最近傍データの距離)を最大化**する二値分類器が基本。多クラスには二値分類器を組み合わせる。
- **OvR(One-vs-Rest / One-vs-All)**:K個の分類器。各分類器は「クラスk vs その他」。予測は最もスコアが大きいクラス。
- **OvO(One-vs-One)**:K(K−1)/2個の分類器。全クラスの組み合わせごとに学習し、**多数決**で決める。

| 項目 | OvR | OvO |
|---|---|---|
| 分類器の数 | K個 | K(K−1)/2個 |
| 1個あたりの学習データ | 全データ | 2クラス分のみ(少ない) |
| 問題点 | 「その他」側が大きく**不均衡**になりやすい | クラス数が多いと分類器数が爆発 |
| よく使われる場面 | ロジスティック回帰など | カーネルSVM(学習データが小さく済むため) |

### 4-4. クラス不均衡への対処
| 手法 | 内容 | 長所 | 短所 |
|---|---|---|---|
| アンダーサンプリング | 多数派を減らす | 学習が速い | 情報の損失 |
| オーバーサンプリング | 少数派を増やす(単純複製、SMOTEなど) | 情報を捨てない | 過学習しやすい |
| SMOTE | 少数派の近傍点の間に合成データを作る | 単純複製より汎化しやすい | ノイズ生成の恐れ |
| クラス重み | 少数派の誤分類の損失を大きくする | データを変えない | 重み設計が必要 |
| 閾値調整 | 判定のしきい値を変更 | 後から調整可 | 適切な閾値を検証データで選ぶ必要 |
| 評価指標の変更 | Accuracy以外を使う | 実態を把握 | 学習自体は改善しない |

### 4-5. 評価指標
混同行列(予測×正解の表)から計算。TP(真陽性)、FP(偽陽性)、FN(偽陰性)、TN(真陰性)。
- **Accuracy** = (TP+TN) / 全体 … 不均衡データでは不適切になりがち
- **Precision(適合率)** = TP / (TP+FP) … 「陽性と予測したうち本当に陽性の割合」。誤検出を減らしたいとき重視
- **Recall(再現率)** = TP / (TP+FN) … 「本当の陽性のうち見つけられた割合」。見逃しを減らしたいとき(病気の検出など)重視
- **F1スコア** = 2PR / (P+R) … PrecisionとRecallの**調和平均**
- 多クラスの平均の取り方:**マクロ平均**(クラスごとの指標を単純平均。少数派も平等に扱う)/ **マイクロ平均**(全体でTP,FP,FNを合計して計算)/ 重み付き平均。

## 5. その他の選択肢・関連用語
他の選択肢は不明だが、**適切な説明**として出やすい内容は次の通り:
- 「ロジスティック回帰はソフトマックス関数で多クラスに拡張できる」→ 適切
- 「SVMは本来二値分類であり、OvRやOvOで多クラスに拡張する」→ 適切
- 「不均衡データではAccuracyだけで評価すべきでない」→ 適切
- 「少数派クラスの重みを大きくする」→ 適切

## 6. 具体例
不正検知:正常99.5%、不正0.5%。常に「正常」と答えるモデルはAccuracy 99.5%だが、Recall(不正の検出率)は0%で実用にならない。

## 7. 類似技術との比較
- 多クラス分類 vs マルチラベル分類 vs 回帰:出力が「1つのカテゴリ」/「複数カテゴリの同時付与」/「連続値」。
- ソフトマックス(クラス間で競合し合計1)vs シグモイド(各クラス独立。マルチラベルで使う)。

## 8. G検定での重要ポイント
- 不均衡データ → Accuracyは不適切、F1・Recall・Precision・AUCなどを見る。
- OvR/OvOの数(K個 / K(K−1)/2個)。
- ソフトマックスは出力の合計が1。

## 9. 間違えやすいポイント
- 「不適切なものを選べ」で、適切な文を選んでしまう。
- 「アンダーサンプリングは少数派を減らす」と逆に覚える。(減らすのは**多数派**)
- OvOとOvRの分類器の数の取り違え。
- Precision と Recall の分母の取り違え(Precisionの分母=予測陽性、Recallの分母=実際の陽性)。

## 10. 覚え方
- **P**recision = **P**redicted positive が分母、**R**ecall = **R**eal positive が分母。
- 「OvO=総当たり戦(リーグ戦)=K(K−1)/2試合」「OvR=1人 vs 全員」。

# 第2問:アンサンブル学習

## 1. 問題の概要
アンサンブル学習との関連が**最も薄い**手法を選ぶ問題。

## 2. 正解
ナイーブベイズ

## 3. 正解となる理由
ナイーブベイズは、ベイズの定理と「特徴量同士が**クラスが与えられたとき条件付き独立**」という仮定に基づく単体の確率的分類器。複数モデルを組み合わせる枠組み(アンサンブル)そのものではない。
他の選択肢(元問題では、おそらくバギング・ブースティング・ランダムフォレスト系)は、いずれも複数モデルの組み合わせに関わる。
【注意】ナイーブベイズを弱学習器としてバギング等に使うこと自体は理論上可能。ここでの「関連が薄い」は「代表的なアンサンブル手法ではない」という意味。

## 4. 関連技術の仕組み

### 4-1. アンサンブル学習とは
複数の学習器(モデル)の予測を組み合わせて、単体より精度・安定性を高める方法。「三人寄れば文殊の知恵」。分類は多数決、回帰は平均が基本。

### 4-2. ブートストラップ法
元データから**重複を許して**同じ件数をランダムに取り出す(復元抽出)。1回のサンプルに含まれない元データは約 (1−1/n)^n → 約36.8%(**OOB:Out-Of-Bag**データ。検証に使える)。

### 4-3. バギング(Bagging = Bootstrap Aggregating)
1. ブートストラップで複数の訓練データを作る。
2. 各データで独立にモデル(例:決定木)を学習(**並列**に可能)。
3. 多数決/平均で統合。
- 主な効果:**バリアンス(データの揺れによる予測のばらつき)を減らす**。過学習の抑制。
- 代表例:**ランダムフォレスト**(バギング+各分岐で使う特徴量もランダムに選ぶ → 木同士の相関が下がる)。

### 4-4. ブースティング(Boosting)
1. 弱学習器(精度が低いモデル。浅い決定木など)を**逐次**に学習。
2. 前のモデルが間違えた部分を次のモデルが重点的に学習。
3. 重み付きで統合。
- 主な効果:**バイアス(モデルの表現力不足による偏り)を減らす**。
- 並列化しにくい。ノイズ・外れ値に敏感になりやすい。
- 代表例:
  - **AdaBoost**:誤分類したサンプルの**重みを増やし**、次の学習器がそこを重視。学習器にも精度に応じた重みを付ける。
  - **勾配ブースティング(Gradient Boosting)**:損失関数の**負の勾配(二乗誤差なら残差)**を次のモデルで予測して足し込む。F_m(x) = F_{m-1}(x) + η・h_m(x)(η:学習率、h_m:新しい木)。
  - **XGBoost**:勾配ブースティングの高速・正則化付き実装。
  - **LightGBM**:ヒストグラム化・葉単位(leaf-wise)の木成長などで高速。大規模データ向け。
  - (補足)CatBoost:カテゴリ変数の扱いに強い。

### 4-5. スタッキング(Stacking)
複数の異なるモデルの予測を**特徴量**として、別のメタモデルが最終予測を行う。

### 4-6. バイアスとバリアンス
- 期待誤差 ≒ バイアス² + バリアンス + ノイズ
- 単純なモデル → 高バイアス・低バリアンス(**過少適合**)
- 複雑なモデル → 低バイアス・高バリアンス(**過学習**)

| | バギング | ブースティング |
|---|---|---|
| 学習の進め方 | 並列(独立) | 逐次(前の結果に依存) |
| 主に減らすもの | バリアンス | バイアス |
| 基本学習器 | 深い木など(低バイアス・高バリアンス) | 浅い木など(弱学習器) |
| データの扱い | ブートストラップ | 誤りに重みを付ける/残差を学習 |
| 外れ値・ノイズ | 比較的頑健 | 敏感になりやすい |
| 代表例 | ランダムフォレスト | AdaBoost、勾配ブースティング、XGBoost、LightGBM |

## 5. その他の選択肢・関連用語
- **決定木**:条件分岐で分類/回帰。単体はバリアンスが大きい → アンサンブルの基本学習器に最適。
- **ナイーブベイズ**:P(y|x) ∝ P(y) Π P(x_i|y)。高速、少量データ・テキスト分類(スパム判定)で有名。
- **ランダムフォレスト**:バギング系。特徴量重要度が得られる。

## 6. 具体例
- 100本の決定木をランダムフォレストで多数決 → 1本の木よりぶれにくい。
- 勾配ブースティングで住宅価格予測:最初の木の予測誤差(残差)を次の木が学習…を繰り返す。表形式データのコンペ(Kaggle)で定番。

## 7. 類似技術との比較
決定木(単体)/ランダムフォレスト(バギング+特徴量ランダム)/勾配ブースティング(逐次)/ナイーブベイズ(確率モデル)の違い。ナイーブベイズだけが「木」でも「組み合わせ」でもない。

## 8. G検定での重要ポイント
- バギング=並列・バリアンス低減、ブースティング=逐次・バイアス低減。
- ランダムフォレスト=バギングの一種。
- XGBoost、LightGBMは勾配ブースティング系。

## 9. 間違えやすいポイント
- 「ランダムフォレストはブースティング」と誤る(正:バギング系)。
- 「ブースティングは並列学習」と誤る(正:逐次)。
- 「バギングはバイアスを減らす」(主目的はバリアンス低減)。
- ナイーブベイズの「ナイーブ(単純)」=条件付き独立の仮定が単純すぎる、の意味。

## 10. 覚え方
- **バ**ギング=**ば**らばら(並列)に学習/**ブ**ースティング=**ぶ**ち込み式に前の誤りを修正(逐次)。
- 「バギングはバリアンス、ブースティングはバイアス」と頭文字(バ・バ/ブ・バ…)ではなく「**ギ**ング→ばらつき(分散)を**ギ**ュッと抑える」など自分流に。

# 第3問:Source-Target Attention

## 1. 問題の概要
Source-Target Attentionに関する空欄補充(A)(B)。

## 2. 正解
(A)Transformer (B)トークンの関連性

## 3. 正解となる理由
Source-Target Attention は、Transformer の**デコーダーがエンコーダーの出力を参照する**ために使うAttention。入力系列(Source)と出力系列(Target)の**トークン間の関連度(重み)**を計算し、出力を作るときに入力のどこを重視するか決める。
【注意】元の文章の文脈が分からないため、(A)(B)の文を断定的には復元していない。「CEC」は LSTM の仕組み(誤差を保持するための内部ループ)で、Attentionではない点に注意(ひっかけの定番)。

## 4. 関連技術の仕組み

### 4-1. Attentionの基本
入力の各要素にどれだけ注目するかを**重み**として学習し、重み付き和を取る。

**Scaled Dot-Product Attention**
Attention(Q, K, V) = softmax(Q Kᵀ / √d_k) V
- **Q(Query)**:「何を探しているか」(検索クエリ)
- **K(Key)**:「各要素の見出し」(検索対象のインデックス)
- **V(Value)**:「各要素の中身」(実際に取り出す情報)
- d_k:Keyの次元数。√d_k で割るのは、内積が大きくなりすぎてsoftmaxが極端になる(勾配が小さくなる)のを防ぐため。
- QとKの類似度 → softmaxで重みに → Vを重み付き和。

### 4-2. Self-Attention と Cross-Attention
| | Self-Attention | Source-Target(Cross)Attention |
|---|---|---|
| Q/K/V の出どころ | すべて**同じ系列** | Qは**デコーダー**、K・Vは**エンコーダー出力** |
| 役割 | 系列内の要素同士の関係(文脈)を捉える | 入力と出力の対応づけ(翻訳での単語対応など) |
| 配置 | エンコーダー、デコーダー両方 | デコーダーのみ |

- デコーダーのSelf-Attentionは**マスク付き**(未来のトークンを見えなくする。生成時に答えを先読みしないため)。
- **Cross-Attention** は一般名。Source-Target Attention はその機械翻訳的な呼び方。画像生成(Stable Diffusion)で、画像特徴(Q)がテキスト埋め込み(K,V)を参照するのも Cross-Attention。

### 4-3. Multi-Head Attention
Q,K,Vを複数の「ヘッド」に分けて並列にAttentionを計算し、結合。異なる観点(文法的関係、意味的関係など)を同時に捉える。

### 4-4. Transformerの構成
- **エンコーダー**:Self-Attention → フィードフォワード層(残差接続+Layer Normalization)
- **デコーダー**:マスク付きSelf-Attention → Source-Target Attention → フィードフォワード層
- **位置エンコーディング**:Attentionは語順情報を持たないので、位置の情報を足す。
- RNNを使わず**並列計算**が可能 → 大規模学習に有利。

### 4-5. 発展
- **BERT**:エンコーダー部分のみ(双方向、穴埋め=Masked LM)。理解タスク向け。
- **GPT**:デコーダー部分のみ(左から右へ次トークン予測)。生成向け。
- **T5/元のTransformer(機械翻訳)**:エンコーダー・デコーダー両方。
- RNN+Attention(Bahdanau, Luong):Attentionの起源。Transformerで「RNNなしでAttentionだけ」へ("Attention Is All You Need", 2017)。

## 5. その他の選択肢・関連用語
他の選択肢は不明。ひっかけとして出やすい用語を整理する:
- **トークン**:処理の最小単位(単語、サブワード、文字)。
- **CEC(Constant Error Carousel)**:LSTMのセル状態を通る経路。誤差が減衰せずに流れ、勾配消失を緩和する。Attentionとは無関係。
- **LSTM**:ゲートで長期依存を扱うRNN。

## 6. 具体例
英→日翻訳 "I love cats" → 「私は猫が好き」。「猫」を出力するとき、Source-Target Attentionは入力の "cats" に大きな重みを置く。

## 7. 類似技術との比較
- RNN:逐次処理・長距離依存が苦手 / Transformer:並列処理・任意の距離のトークンを直接参照。
- Attentionの計算量:系列長nに対して O(n²)(長文でコストが大きい)。

## 8. G検定での重要ポイント
- Source-Target Attention=デコーダーがエンコーダー出力を参照。
- Self-Attention=同一系列内。
- Q,K,V の役割、Multi-Head の意味。
- Transformer=Attention中心、RNN不使用。

## 9. 間違えやすいポイント
- 「Source-Target AttentionはRNN/LSTMの仕組み」は誤り。
- 「CEC」を Attention と混同。
- Self-Attention と Source-Target の Q,K,V の出どころの違い。
- BERT(エンコーダー)とGPT(デコーダー)の取り違え。

## 10. 覚え方
- **Q**uery=質問者、**K**ey=名札、**V**alue=持ち物。質問に合う名札を探して、その人の持ち物をもらう。
- Source(入力側)を見て Target(出力側)を作る=翻訳者が原文を見ながら訳文を書く。
